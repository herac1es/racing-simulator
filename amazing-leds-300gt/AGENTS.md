# RPM 灯效开发原则

本文件约束 amazing-leds-300gt 后续的源码、生成配置和校准工作。

- 用户没有明确指定例外时，以 iRacing 车内实际 RPM 灯组为目标，保持点亮方向、空间顺序、颜色、每挡每灯触发时机，以及红线/闪烁行为。不能为了更好看、填满灯条或补偿输出延迟而自行改变这些行为。
- 必须结合 iRacing 官方车辆手册、SDK/遥测和更新说明核对方向、配色及阶段，不仅凭 Lovely 数组推断原车布局。Lovely 是补充数据来源；有明确的游戏实测偏差时按车型、挡位、RPM 和视频定位、校准。旧手册不自动等于现行 EVO 数据，未验证的结果不能宣称完全同步。出处与适用范围见 `docs/iracing-rpm-evidence.md`。
- 10 个有效原车灯位扩展到 300 GT 的 12 灯时，前面八颗各对应一颗灯珠，原车最后点亮的两颗分别对应两颗相邻的方向盘灯珠。每对使用同一来源灯的颜色、阈值和状态，不能插值出新阶段。
- “最后两颗”按原车点亮顺序判断，不固定指物理最右侧两颗。保留原车布局方向：单向点亮的末两颗各复制一次；两侧向内的最后两颗位于中央，扩展为中央四颗。原车末两颗若分开点亮，两个双灯组也必须按各自原始时机分别点亮，不能提前合并。
- BMW 不得使用 2024 年 V3 旧款 M4 GT3 手册的 4800–6600/6800 单表作为 EVO 基线；用户已指出其数据不符。恢复 Lovely 分挡时机，以用户确认的左到右方向作临时映射：来源顺序 `[1,12,2,11,4,9,5,8,6,7]`，扩展为 `[1,12,2,11,4,9,5,8,6,6,7,7]`。保留五个来源阶段，不插值十阶段；右端两个双灯组各继承来源 6、7 的原始状态。此适配尚未验证当前 EVO 的逐灯布局与颜色，不能称为官方 EVO 数据或完全同步。CarId 沿用不能证明历年灯效参数相同。旧手册仅作历史记录，后续使用官方资料前必须核对车型版本及适用范围。
- 不把 10→12 规则套到 Porsche 等 16 灯车型。沿用已记录的映射，明确其省略阶段的限制；调整其他灯数的映射时单独处理。
- 缺少车型数据时，保留现有明确标注的通用回退，不把估算方向、颜色或阈值描述成原车复现，也不擅自删除已有回退功能。
- 优先通过 SimHub 原生 UI 节点暴露调参入口。用户明确的 UI 调整可以作为例外；同步回仓库时记录依据，修改源码并重新生成 profiles，不只修改生成文件。
- 保留原始 vendor 数据、哈希和第三方署名/许可。用与改动相匹配的测试验证映射、时机和层级；未经用户明确要求，不合并 PR。
